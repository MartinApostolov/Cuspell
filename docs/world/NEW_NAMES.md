# Cuspell New Names

_Status: generic/core New Name registry only_

This document is for **New Names that belong to Cuspell itself or to the generic/current Cuspell world**, not for names imported from a particular book, setting, campaign, or test corpus.

The machine-readable source of truth is:

- `world/core/new_names.json`

Current generic/core New Names: **0**.

That is intentional. So far, all registered New Names have come from setting-specific corpus packages such as Yona, and those remain in their own package rather than being copied here.

## What belongs here

A New Name belongs in this document when the referent is part of Cuspell's own current/post-cutoff vocabulary rather than a historical Old Name.

Typical examples would be:

- a person or unique object from Cuspell's own setting;
- a newly coined current-era technical term;
- a later institution, profession, scientific category, magical school, or named artifact that did not exist before the Old-Name cutoff;
- a current proper place/person/object name in the Cuspell world.

New Names are ordinary Name/reference relations. They do **not** gain magical macro/compression privilege merely because they have a registered Sign.

## What does not belong here

Do not copy setting-specific/book-specific names into this registry.

For example, Yona names remain under:

- `world/yona/new_names.json`

Future book/campaign test packages should likewise stay under their own `world/<package>/new_names.json`.

This document should remain a clean view of **our language/world's own current New Names only**.

## Old Names are separate

Historical pre-cutoff vocabulary lives in:

- `language/names/old_names.json`
- `docs/world/FIRST_CIVILIZATION_VOCABULARY.md`

Old Names may carry frozen historical magical compression. New Names do not.
